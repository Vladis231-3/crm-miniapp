## 1. Цели и критерии успеха

### 1.1 Продуктовые цели
1. Один узнаваемый бренд во всех 5 поверхностях (TG Mini App ×4 роли, 3 веб-лендинга, десктоп).
2. Предсказуемая навигация: любой экран достигается ≤3 тапов; у каждого экрана есть «адрес» (deep-link).
3. Единая дизайн-система: ни одного цвета/отступа/тени вне токенов.
4. Премиальное ощущение: стекло, плавность, микроанимации, аккуратная типографика — уровень топовых detailing-студий.

### 1.2 Измеримые критерии приёмки (финал проекта)
- [ ] `rg '#[0-9a-fA-F]{3,8}' src/app --glob '!**/styles/**'` в frontend → **0 вхождений** вне файлов токенов (хардкод цветов уничтожен).
- [ ] Контраст обеих тем ≥ WCAG AA (4.5:1 текст, 3:1 крупный текст/иконки) — проверено инструментом на всех экранах.
- [ ] Все интерактивные элементы ≥ 44×44 px hit-area.
- [ ] Ни один чанк бандла роли > 350 KB gzip; первичный входной чанк < 250 KB gzip.
- [ ] `npm run build` зелёный во всех трёх пакетах; консоль браузера без ошибок/варнингов React на каждом экране.
- [ ] Каждый из ~35 целевых экранов имеет скриншоты light/dark в `design/screens/` и пройденный QA-чеклист (§11).
- [ ] Мёртвые зависимости удалены (MUI, emotion, react-dnd, react-slick, canvas-confetti, next-themes, react-router* — см. §10.3), `_OwnerApp.work.bak.tsx` удалён.
- [ ] PWA-манифест, favicon-набор, og-image на месте; Electron-иконка = новый логотип.

### 1.3 Антицели (не делаем)
- Не меняем бэкенд-контракты, модели БД, бизнес-логику расчётов.
- Не вводим новые тяжёлые библиотеки без обоснования (запрет: добавить CSS-framework №2, анимационную либу №2).
- Не делаем мультиязычность (только ru), не меняем формат дат DD.MM.YYYY HH:mm и валюту ₽.
- Не трогаем `training/` (замороженная копия) — только в самом конце решить: удалить или синхронизировать.

- P2: рядом с продом лежит битая копия `_OwnerApp.work.bak.tsx` (780 KB, сломанная кириллица).

**Дизайн-система:**

### 4.3 Сетка и отступы

- Базовый шаг **8px**, микро-шаг 4px.
- Скрин-паддинги CRM: mobile 20px, ≥768px 32px. Контентная макс-ширина CRM: 720px (одно-колоночные потоки) / 1100px (дашборды).
- Отступы между блоками: 12/16/24/32 (только эти значения; соответствуют space-2..5).
- Лендинги: контейнер max-width 1200px, gutters 20/40.
- Touch-target: визуально 40px допустимо, hit-area ≥44×44 (padding-компенсация).

### 4.4 Радиусы, тени, стекло

Радиусы: chip/pill `999px`; button/input `12px`; card `16px`; sheet `20px` (верхние углы); modal `24px`; hero/media `20px`.

Тени (сохраняем шкалу, добавляем CTA-glow):
`xs 0 1px 2px rgb(16 18 23/.05)` · `sm 0 1px 3px /.07` · `md 0 2px 10px -2px /.09` · `lg 0 12px 32px -8px /.14` · `xl 0 20px 50px -12px /.18` · `glow-primary 0 8px 24px rgb(79 70 229/.35)` (тёмная тема, только главная CTA потока записи).

**Стекло (glass) — три уровня, правила применения:**

| Уровень | Состав | Где разрешено |
|---|---|---|
| glass-1 | fill: white .72 (L) / white .05 (D) + blur(12px) + border 1px --border | вложенные карточки поверх цветных подложек, слоты календаря |
| glass-2 (chrome) | color-mix(bg 86%) + blur(24px) saturate(140%) | header, нижняя/боковая навигация — максимум 2 таких зоны на экране |
| glass-3 | градиент поверх изображения (black .75→.0) | hero лендингов, баннеры |

Запрещено: стекло на стекле (наложение glass-1 внутрь glass-2 без solid-подложки), стекло на элементах < 44px, более 2 blur-слоёв одновременно во вьюпорте (производительность). Fallback: `@supports not (backdrop-filter: blur(1px))` → непрозрачные --card.

### 4.5 Motion

Тайминги сохраняем: `fast 140ms / base 220ms / slow 360ms`, easing `cubic-bezier(.2,.8,.2,1)`.

| Событие | Спецификация |
|---|---|
| Вход экрана | opacity 0→1 + translateY 10px→0, 340ms (класс `.page-enter`) |
| Sheet снизу | translateY 100%→0, 260ms tween + затемнение фона 180ms |
| Modal по центру | scale .96→1 + fade, 260ms (`.pop-enter`) |
| Spring-пилюля навигации | motion `layoutId`, `{type:'spring', stiffness:500, damping:38}` |
| Press на контроле | scale .975, 140ms (уже глобально — сохранить) |
| Выбор слота | scale до 1.04 + заливка primary-600, 140ms |
| Toast | сверху под header, slide-down 220ms, автоскрытие 4s |
| Skeleton | pulse 1.4s ease-in-out infinite |
| prefers-reduced-motion | всё глушится (правило уже есть — не потерять при миграции) |

### 4.6 Z-index шкала

`content 0 · sticky-header 20 · nav 30 · dropdown/popover 40 · sheet 50 · dialog 60 · toast 70 · tooltip 80`. Только эти значения, никаких ad-hoc `z-[999]`.

### 4.7 Брейкпоинты (единая система)

Ввести hash-синхронизацию: `#/admin/calendar`, `#/owner/finance/salary/42`, `#/client/bookings`.
Механика: единый `useHashRoute()` (parse на старте, pushState при смене страницы/детали), интеграция с существующими useState-«страницами». Даёт: ссылочная адресация, поведение «назад», восстановление экрана после перезапуска — без переписывания навигации.
Полный react-router — осознанно отложен (стоимость миграции > пользы при текущем SPA-характере).

### 10.5 Производительность
- `hero-bg.jpg` 1.97MB → AVIF/WebP ≤ 250KB + `<link rel=preload>`; остальные фото лендингов — `loading="lazy"` + width/height (CLS).
- Code-split: каждая роль — `React.lazy()` (чанки уже греются в vite.config — пересмотреть список warmup после разреза).
- recharts — динамический import внутри ChartCard.
- backdrop-filter: не больше 2 активных зон (§4.4) — контроль при ревью.

## 14. Бэклог вне v2 (требует изменений бэкенда — осознанно исключено из объёма)

Идеи, отклонённые антицелью «не меняем бэкенд». Не реализовывать в рамках этого редизайна; вернуться отдельным проектом:

1. **Копилка/бонусы клиента** — таб с балансом депозитов требует клиентских GET-роутов (сейчас всё под `/api/owner/deposits*`, bootstrap клиента пустой).
2. **Перенос записи клиентом** — PATCH `/api/bookings/{id}` закрыт для роли client.
3. **Реальные чеки мастеров** — сейчас только локальная нотификация (WA:508).
4. **Напоминание за 60 минут** — cron шлёт за день; изменение окна — бэкенд+cron-конфиг.
5. **Testimonials в контент-API** — поле в ContentPayload; до тех пор — редактируемый хардкод.
6. **Мгновенное бронирование vs заявка** — сейчас статус жёстко `admin_review`; UX уже честно коммуницирует «заявку».
